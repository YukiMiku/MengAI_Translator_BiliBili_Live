# AI萌译酱 v1.4.11（分发版）

[中文](README.md) | [日本語](README.ja.md)

> 日语界面下的名字是 **萌AIちゃん** —— 切换界面语言时，**窗口标题、控制台标题、OBS 停靠页标题会一起切换**。
>
> 版本号以 `version.py` 为唯一来源；目录名、压缩包名、窗口标题、自检输出都与之保持一致。

## 环境要求

### 分发版（GitHub Releases 下载的便携包）

- Windows 10 / 11（64 位）
- **不需要自己装 Python**：便携包自带 Python 3.14.7 运行时（含手工补入的 `tkinter`）
- 安装目录是 `install.bat` 所在目录下的 `萌AIちゃん`（日语版 Windows 直接用没问题；非日语版请用 `-Dest` 指定 ASCII 路径）
## 启动

1. 双击 `install.bat` 安装：它会从 GitHub Releases 下载便携包，解压安装到
   **`install.bat` 所在目录下的 `萌AIちゃん`**，并**自动在桌面创建快捷方式**
   （同时会问你是否顺带选装 Pillow）。
2. 安装完成后，**直接双击桌面上出现的快捷方式**即可启动
   （快捷方式指向安装目录里的 `launch.bat`）。
3. 界面默认日语，启动后可在界面里切回中文。
4. 升级：再双击一次 `install.bat` 即可（覆盖安装），`data/` 会自动保留。

### 关于安装位置（分发版需要留意的地方）

- 安装目录默认是 **`install.bat` 所在目录 \ `萌AIちゃん`**；目录名**不带版本号**，
  这样桌面快捷方式才能长期有效。
- **建议把 `install.bat` 放在纯 ASCII 路径下**再安装，例如 `D:\MengAI\`。
  如果路径里有特殊字符（emoji、生僻字，或当前系统代码页表示不了的字符），
  快捷方式可能失效、程序也可能打不开。
- 想装到别处就用 `-Dest` 指定：

  ```bat
  install.bat -Dest "D:\MengAI"
  ```

  这样程序会装在 `D:\MengAI\萌AIちゃん`，快捷方式也按这个路径创建。
  想同时选装 Pillow 可以加 `-Pillow Yes`（可选 `Yes` / `No` / `Ask`）：

  ```bat
  install.bat -Dest "D:\MengAI" -Pillow Yes
  ```

- 桌面快捷方式丢了不用重装：到安装目录双击 `launch.bat` 一样能启动；
  也可以再跑一次 `install.bat` 让它把快捷方式重建出来。

## 启动不了怎么办

分发版是「安装式」的，所以先排查**安装**这一层，再排查程序本身：

1. **确认装完整了**：打开安装目录 `萌AIちゃん`，正常应该能看到
   `launch.bat`、`python\python.exe`、`app.py`、`public\`、`data\` 等。
   如果缺 `python\` 或明显不全，说明安装被中断（多半是杀毒软件拦截或下载中断），
   **重新双击 `install.bat`** 即可。
2. **双击安装目录里的 `check.bat`**：它会把运行时、工程文件、端口、目录权限逐项检查
   并打印结果，把结果截图发我就能定位。
3. **桌面快捷方式点了没反应**：
   - 右键快捷方式 → 属性，看「目标」是否指向 `…\萌AIちゃん\launch.bat`；
     那个路径若已不存在（例如你移动或改名过安装目录），快捷方式自然失效。
   - 处理办法：删掉旧快捷方式，重新跑一次 `install.bat`（它会按当前路径重建）；
     或者安装时用 `-Dest` 指定一个**纯 ASCII 路径**再创建快捷方式。
4. **窗口一闪而过 / 完全没反应**：改用安装目录里的 `debug.bat` 启动，
   错误会留在控制台窗口里；程序目录下若生成 `启动错误.txt`，里面是完整堆栈。
5. **杀毒软件拦截**：把整个安装目录加入白名单。首次运行若出现
   Windows 的「已保护你的电脑」，点「更多信息 → 仍要运行」。
6. **提示端口被占用**：本程序要占用本地端口 **17890**；若提示冲突，
   先关掉已在运行的另一个本程序实例（或占着该端口的程序）再试。
7. **安装卡在下载**：换网络重试；也可以手动下载 Releases 里的压缩包，
   解压到你想要的位置后直接双击里面的 `launch.bat`
   （这样不会创建桌面快捷方式）。

## v1.4.9 修复

### 切换配色后，礼物区 / 入场区底色不跟着变

**症状**：首次启动是黑色时，把配色换成奶白 / 天蓝 / 粉色，**礼物区和入场通知区仍然是黑的**
（弹幕区是正常的）。

**原因**：礼物区、入场区这些是 tkinter 的 `tk.Text` / `tk.Canvas` / `tk.PanedWindow`，
**不受 ttk 样式表管辖**，必须在换肤时手工重涂。而换肤函数里那份手工清单**漏了它们**
（弹幕区在清单里，所以只有它是好的）。

**修复**：把漏掉的一并补进换肤逻辑，并且**做了一次彻底排查**，同类问题一共修了 7 处：

| 控件 | 之前的症状 |
| --- | --- |
| 礼物区 `tk.Text` | 一直保持启动时的底色（你发现的） |
| 入场区 `tk.Text` | 同上（你发现的） |
| System Prompt 编辑框 | 连底色都没设，一直是系统默认浅色 |
| 各标签页的滚动容器 | 停在启动时的底色 |
| 外层竖直分栏 `tk.PanedWindow` | 停在启动时的底色（礼物区外框） |
| 礼物区内部左右分栏 `tk.PanedWindow` | 同上 |
| 警告条上的「去登录」按钮 | 强调色不跟着变 |
| README 说明窗口 | 独立窗口，建好后不跟着变 —— 现在换配色时自动关闭，再点「説明」会用新配色打开 |

**验证方式**：从黑色启动后逐个切换四套主题，**遍历整棵控件树**检查每个非 ttk 控件的底色
是否都属于当前主题 —— 四套主题、来回切换，残留数量均为 **0**。

## v1.4.5 新增：入场通知、字号层级、上舰 / SC

### 1. 入场通知（礼物区一分为二）

原本的礼物区现在**分成两块**，中间的分隔条可以拖动：

- **上半 · 礼物 / 上舰 / SC**：原来那些内容，另外多了两类付费事件（见下）；
- **下半 · 入场**：显示「时间 + ID」，并在下一行给出 **ID 的拼音**。
  **纯英文、日文假名、数字的 ID 不注音**（只给汉字出拼音），所以不会出现空荡荡的拼音行。

### 2. 字号层级：原文 > 拼音 > 新ID(=译文) > 旧ID

| 层级 | 用在哪 |
| --- | --- |
| **原文**（最大） | 弹幕原文、礼物名、SC 正文 |
| **拼音** | 注音（弹幕、入场 ID、礼物名、SC 正文） |
| **新 ID = 译文** | 入场通知的 ID、礼物 / 上舰 / SC 区的用户名 |
| **旧 ID**（最小） | 弹幕里原有的那行「时间 + 用户名」 |

「外观」里仍然只调三个字号（原文 / 注音 / 译文），**新 ID 跟随译文、旧 ID 自动比译文小两号**，
程序会按这个层级自动钳制，怎么调都不会乱。

### 3. 上舰 / SC 通知

- **上舰**：`时间  用户名  开通了` + `舰长 / 提督 / 总督 ×N`；
- **SC（醒目留言）**：`时间  用户名  醒目留言 ¥30（60秒）` + 正文，正文同样带拼音。

### 4. 礼物抓取更准（重要）

B 站把礼物事件的报文体换成了 **protobuf**（`SEND_GIFT_V2` 的 `data` 里只有一个 base64 的 `pb`，
原来的 `giftName` / `uname` / `num` 全没了），所以 1.4.3 及更早会出现「礼物不显示」。
现在程序**自解析 protobuf**（不引第三方库），并且：

- **只要 `pb` 在就按礼物解**，不再依赖事件名 —— 服务端以后再改名也不怕；
- **解不出礼物名就不产生任何行**（绝不显示一条分不清是什么礼物的记录）；
- 收到但没解析出来的「礼物类事件」会写进日志，并把 `business_label` / 字段名一起打出来，
  方便照着重补；
- 每 120 秒汇总一次收到的消息类型，礼物到底有没有被推送，看日志就知道。


## v1.4.0 新增：拼音注音 + 礼物栏

### 1. 弹幕原文的逐字拼音注音（带声调）

中文弹幕会在**原文上方逐字显示带声调的拼音**：

```
zhè shǒu gē zhēn de tài hǎo tīng le
这 首 歌 真 的 太 好 听 了
→ この歌は本当にいいね
```

- **只给中文加注音**：日文、英文、数字、标点、表情原样显示，不会硬凑；
- **字号层级**：原文 > 注音 ≥ 译文，三个字号都能在「外观」里单独调整；
- 拼音**只用于显示，绝不参与翻译**（送进模型的始终是原文）；
- 「外观」里有开关，不需要时一键关掉（关掉后画布项数少约 82%，更省资源）；
- 拼音引擎用的是 **pypinyin（MIT）**，已随包附带在 `lib\` 下，**离线可用**；
- 词库里的拼音列是注音的「覆盖层」——手动填的优先于引擎结果，适合多音字和网名；
- OBS 停靠页用原生 `<ruby>` 渲染，注音与原文一个字一个字对齐。

### 2. 礼物栏

礼物栏从弹幕区下半部分切出来，中间的分隔条可以拖动：

- **礼物文字不翻译**（礼物名本身就是日语或通用词），但**保留拼音注音**；
- **连击只显示最终数目**：同一个人同一批连击只更新那一行的数量，不会刷屏；
- **同一个人在不同时间送同一个礼物不会合并**，各自成行，方便回看；
- **不设条数上限**，可以直接回溯、筛选历史（筛选是分批做的，界面不会卡住）；
- **免费礼物（银瓜子 / 价格为 0）可过滤**，开关默认**关闭**（小主播的礼物也看得到）；
- 礼物记录**和弹幕一样，重启后清空**；
- OBS 停靠页同步显示，默认显示最近 **30 件**，滚到顶部会自动加载更早的。

## B 站登录（解决昵称打码）

### 现象

不登录时，B 站可能把弹幕发送者的昵称返回成 **`首字***`**，同时把 **uid 置为 0**：

```
21:57:06  雪***          ← 实际是 雪初音天下第一可爱
膨らんだら針付きのあの魚？フグじゃない？
```

这不是本程序的 bug（程序里没有任何打码逻辑，字符串是 B 站直接下发的），
而是 B 站自 2023 年 7 月起的风控策略：**未登录的连接会被判定为匿名客户端，从而被打码**。
[LAPLACE Chat](https://laplace.live/login-sync) 的说明是「由于哔哩哔哩本身的限制，我**不得不**获取您的通行证（cookie）信息，以获得**未打码**的弹幕信息」。

### 解决办法：把 SESSDATA 放进文件（不用登录浏览器）

程序从 `data/bilibili_cookie.txt` 读取登录信息。**不启动任何浏览器、不做任何自动登录。**
**而且只需要 SESSDATA 一个值**：

1. 「连接」页 → 点「**打开 cookie 文件**」（记事本会打开，文件里已写好详细步骤）
2. 浏览器打开 `https://www.bilibili.com`（确认已登录）→ 按 `F12`
   → **Application / 应用程序** → **Cookies** → `https://www.bilibili.com`
3. 找到 **SESSDATA**，双击 Value 全选复制，在文件**最下面新起一行**写成：
   ```
   SESSDATA=你复制到的值
   ```
4. 回程序点「**载入并验证**」→ 成功会显示 `✅ 已登录：<昵称>（uid=xxx）`
5. 重新点一次「连接」——之后弹幕就带**完整昵称**和**真实 UID**

**为什么只要 SESSDATA？**（这也是业界标准库 [blivedm](https://github.com/xfgryujk/blivedm) 的做法）

| 项 | 需要吗 | 原因 |
| --- | --- | --- |
| `SESSDATA` | ✅ 必需 | 唯一的会话凭证，blivedm 只认它 |
| `bili_jct` | ❌ 不用 | 那是**写操作**的防伪令牌；本程序只读弹幕 |
| `DedeUserID` | ❌ 不用 | uid 程序会自动调 `nav` 接口取（`data.mid`） |
| `buvid3` | ❌ 不用 | 程序已通过 SPI 接口自动获取 |

支持的格式（任选）：

| 格式 | 例子 |
| --- | --- |
| **只写 SESSDATA**（推荐） | `SESSDATA=xxx` |
| 只贴 SESSDATA 的值本身 | 不带 `SESSDATA=` 也行 |
| 整行 cookie | `SESSDATA=xxx; bili_jct=yyy; DedeUserID=123` |
| Cookie-Editor 的 JSON / Netscape cookies.txt | 直接整段粘贴 |

### 打码自动检测

程序会实时统计被打码的条数，一旦出现就在顶部显示横幅：

```
⚠ 检测到 12 条弹幕的昵称被 B 站打码（显示为「首字***」、uid=0）。   [去登录]
```

点「去登录」直接跳到「连接」页并打开 cookie 文件。

### 安全提醒（请务必看）

`data/bilibili_cookie.txt` **等同于你的 B 站登录凭证**——拿到它就能以你的身份操作账号。
LAPLACE 为此专门写了整节风险说明并建议**用小号**。

- 不要把这个文件发给任何人、不要传网盘
- 建议**只用小号**来做弹幕机的登录
- 不用这个功能时，点「清除登录信息」把文件重置回模板即可

### 关于「直接从浏览器 cookie 数据库读取」

有人会想到直接解密 Chrome/Edge 的 `Cookies` 数据库。**这条路在现代浏览器上走不通**，实测结论：

| 检查项 | 结果 |
| --- | --- |
| Edge 的 bilibili cookie 加密格式 | **全部 `v20`（App-Bound Encryption）** |
| 能否用 DPAPI + AES-GCM 解密 | **不能**，`v20` 的密钥绑定在浏览器自身，其它程序解不开 |
| Chrome 的 Cookies 数据库 | 被 Chrome 独占锁定，共享模式也读不到（需先关掉 Chrome） |
| Firefox | 存的是明文，本来是可行的，但本机未安装 |

这正是 Chrome 127+ 的设计目的——阻止其它程序窃取 cookie。
所以本程序采用「**你手动导出一次到文件**」的方式：既不绕过系统的安全机制，也只需配置一次。

## 弹幕区背景图：缩放 / 位置 / 不透明度

### 不裁剪 —— **100% 就是原图的原始像素大小**

导入图片时**不会**把图拉伸或裁剪成弹幕区的尺寸：

| 情况 | 行为 |
| --- | --- |
| 图片比弹幕区**大** | 自动等比缩到"整张刚好放得下"（例：1600×1000 → 42%），**一眼就能看到完整图片** |
| 图片比弹幕区**小** | 按**原始大小（100%）**居中显示，四周露出面板底色 |

超出弹幕区的部分由画布自然裁掉（那是画布行为，不是我们在"裁图"），用位置滑块就能把画布外的部分移进来。
日志里会写明原图尺寸和实际用的百分比，例如：`原图 1600x1000，已缩放到 42% 以便整张可见（未裁剪）`。

### 四个控件：滑轨 + **可直接输入数值**

| 控件 | 范围 | 说明 |
| --- | --- | --- |
| **背景图缩放** | 10% ~ 400% | **100% = 原图 1:1** |
| **背景图不透明度** | 0% ~ 100% | 与面板底色混合；0% = 完全看不见图 |
| **背景图水平位置** | -100% ~ 100% | 0% = 居中；±100% = 平移半个画布宽度 |
| **背景图垂直位置** | -100% ~ 100% | 0% = 居中；±100% = 平移半个画布高度 |

每个控件都是「**滑轨 + 数值框**」：

- 拖滑轨，或**直接在数值框里输入数字**（回车 / 点走生效；写 `37%` 也认）
- 数值超范围会夹到边界（输入 `9999` → 400），非法输入保持不变
- 滑轨支持**点击跳转**、拖动、**滚轮微调**（±1）
- 另有两个按钮：「**适应弹幕区**」（把整张图缩到刚好放得下）、「**恢复默认**」（四项一起复位）
- 拖动/输入时**防抖重绘**（约 150ms），松手后自动保存到 `data/config.json`

### 滑轨配色随主题（自绘）

原先用的 `ttk.Scale` 槽与滑块由系统主题决定，在黑色/蓝色等深色预设下**几乎看不见**。
现在滑轨是**完全自绘**的：槽用输入框底色 + 边框描边，已选部分与滑块用该主题的**强调色**，
四套配色下都清晰（实测强调色与槽底色的亮度差 97 ~ 152）。

### 透明 PNG 的处理

导入带透明通道的 PNG（RGBA）时，**透明部分会露出弹幕区底色，不会变成黑底**。

> 黑底来自两个陷阱：Tk 的 `PhotoImage` 导出成 PPM 时只有 RGB，透明像素的 RGB 是 `(0,0,0)`；
> Pillow 的 `convert('RGB')` 同样会把 `(0,0,0,0)` 变成 `(0,0,0)`。
> 本程序改为**先把透明区压平到面板底色**（Pillow 用 `Image.alpha_composite`，
> Tk 路径用 `image copy` 的 alpha 合成），再做缩放与不透明度混合——
> 视觉上等同「完全透明」，边缘也不会出现黑边。

> **实现说明（Tk 没有原生透明度）**：不透明度是把图片导出成 PPM，用 `bytes.translate` 做逐通道查表混合，
> 再把结果装回 `PhotoImage`；整段是 C 级切片运算，一张 760×420 只要几毫秒。
> 缩放用「Tk 整数缩放保证不小于目标 + 精确裁剪」组合，因此**任意百分比都能落到精确像素尺寸**。
>
> 若 Pillow 可用（推荐），会改用它做 LANCZOS 平滑缩放 + `Image.blend`，并对 JPG/WEBP 也有效。

### 预设会连外观一起记住

「保存预设」除了翻译服务 / 提示词 / 并发 / 词库，现在还会记住：

- **配色**（白色 / 黑色 / 蓝色 / 粉色）
- **背景图路径**
- **背景图缩放**
- **背景图不透明度**
- **背景图水平 / 垂直位置**

「读取预设」时这些会一并还原（读取日志里会写明还原成了什么）。

## 版本号规则

三段式 `X.Y.Z`，完整规则写在 `version.py` 顶部（版本号唯一来源）：

| 段位 | 含义 | 触发条件 | 示例 |
| --- | --- | --- | --- |
| `X` | 大版本 | 功能迭代把第二位推到 11 时进位 | `v1.10.0` → `v2.0.0` |
| `Y` | 功能新增 | 每新增一个功能 +1，取值范围 0 ~ 10 | `v1.0.0` → `v1.1.0` |
| `Z` | 仅修 bug | 只修 bug 时 +1，**可无限累计** | `v1.0.0` → `v1.0.1` |

- 第一位一旦变化，第二位与第三位**全部清零**。
- **功能迭代时第三位清零**：`v1.3.7` →（新增功能）→ `v1.4.0`。
- 第三位**不向第二位进位**：修 bug 永远只动第三位。

```
v1.0.0 → v1.0.1（修 bug）→ v1.0.2（修 bug）→ v1.1.0（新功能，第三位清零）
       → v1.2.0 → v1.2.1（修 bug）→ v1.3.0（新功能，第三位再次清零）
       → … → v1.10.0（第二位最后一个可用值）→ v2.0.0（进位，第二、三位清零）
```

发版时改 `version.py` 里的 `APP_VERSION`，再把目录与 zip 改成同名，最后跑 `selfcheck.py` 确认「内外版本号一致」。

### 重要：路径与快捷方式名不能含当前系统代码页表示不了的字符

| 位置 | 结果 |
| --- | --- |

- **快捷方式指向 ASCII 的 `launch.bat`**
- 安装目录 `萌AIちゃん` 在**日语版 Windows 的 Shift-JIS 里可以表示**，直接用没问题
- 实际执行的脚本文件名（`launch.bat` / `check.bat` / `debug.bat`）**一律 ASCII**
- **非日语版 Windows** 上有些字符无法表示，那种情况请用 `-Dest "D:\MengAI"` 指定 ASCII 路径

### 网页版（DeepSeek / ChatGPT）使用方法 —— 不需要安装任何组件

网页版使用**本程序专用的浏览器窗口**（复用你系统里的 Chrome / Edge，不下载内核，也不装 playwright）。

#### 为什么不用你日常那个窗口？

从 **Chrome 136** 起，Google 出于安全考虑**禁止在"默认数据目录"上开启远程调试**
（[官方公告](https://developer.chrome.com/blog/remote-debugging-port?hl=zh-cn)）。
也就是说，程序**没有办法**附加到你平时用的那个 Chrome 上——这是 Chrome 的限制，不是本程序的。
官方给出的替代方案就是"使用一个自定义的数据目录"，本程序采用的就是这个方案。

#### 使用方法

1. 「翻译服务」选「DeepSeek 网页版」或「ChatGPT 网页版」。
2. 点「打开网页端登录」。
   - 首次会**尝试把日常浏览器的登录数据导入**到本程序专用目录。
   - **DeepSeek**：登录态在 `localStorage`（不加密），可以成功带过来，打开就是已登录。
   - **ChatGPT**：登录态是加密 Cookie。从 Chrome 127 起启用了「应用绑定加密」，
     Cookie **无法迁移到别的目录**（这正是 Google 防止 Cookie 被复制窃取的安全设计）。
     所以 ChatGPT 需要**在这个专用窗口里登录一次**，之后会一直记住。
3. 之后所有翻译都在这个专用窗口里进行，程序会在里面**新开 / 复用标签页**。

> 专用目录只会导入一次，**不会**在后续启动时覆盖你已经登录好的会话。
> 想彻底重来就删掉 `data/browser_profile` 目录（删了就要重新登录）。

#### 其它说明

- **建议先在网页端关掉「深度思考」和「联网搜索」**：这两个开关会让每条弹幕的回复变慢很多，
  而且「深度思考」会先输出一段思考过程。程序已经会**自动跳过思考块、只取最终译文**，
  但关掉它速度会快好几倍。
- 专用目录在 `data/browser_profile`。想彻底重来（重新导入登录数据）就删掉这个目录。
- 两个网页版**共用同一个浏览器实例**（各占一个标签页）。
- 程序只复用**自己启动的**浏览器实例，不会误连其它程序占用的调试端口；
  即使换了解压目录（记录丢失），只要调试浏览器还开着就会直接复用，**不会重复开第二个浏览器**。
- 输入/发送使用**浏览器原生输入事件 + 真实回车**，因此每一句弹幕都是独立的新提问，
  不会出现"覆盖上一条提问"的情况；日志里会写出实际的发送方式（`发送方式：输入=native，提交=ENTER`）。
- 程序**不会**注入自动化标记，因此不会出现「Chrome 正受到自动测试软件控制」或
  「不受支持的命令行标记」这类黄条警告。
- 网页版为顺序翻译（并发固定为 1），速度比 API 慢。
- 网页版依赖站点页面结构；若 DeepSeek / ChatGPT 改版导致找不到输入框，
  把日志发我，我调整 `browser.py` 里的 JS 片段即可。

## 本地词库文件

- 默认词库文件：`data/glossary.txt`，每行一条：
  ```
  原词 => 日语译法 # 备注
  ```
  例如：
  ```
  草 => w # 表示笑
  可爱 => かわいい
  草 => くさ（笑）      ← 译文里的括号会原样保留
  ```
- **备注只认 `#`**：`原词 => 译法 # 备注`。
  译文末尾的「（…）」会被当作译文本身（旧版会误当成备注，已修正）。
- 「打开词库文件」用记事本编辑；「导入词库文件」额外支持 CSV（列：source,target,note,enabled）和 JSON（数组 `[{"source","target","note","enabled"}]`）。
- 词库会作为术语规则注入翻译模型，优先采用你指定的译法。
- 行尾写 `[禁用]` 可停用某条，例如 `原词 => 译法 [禁用]`。

### 多个词库（不同场景不同译法）

- 「**新建词库**」按钮：输入名字即在 `data/` 下建立一个新的词库文件（如 `游戏A.txt`、`日常.txt`）。
- 「**当前词库**」下拉框：随时在已有词库之间切换。
- 配合预设使用（推荐）：
  1. 建好词库 → 加词条 → 到「预设」页点「保存预设」；
  2. 该预设就记住了这个词库，预设下拉框会显示 `词库:游戏A.txt`；
  3. 以后「读取预设」，翻译服务 / 提示词 / 并发 / **词库**会一起切过去。
- 这样同一个词（例如「草」）在不同预设里可以有完全不同的日语译法，不会互相干扰。

## 常见问题

- **提示 Python not found**：PATH 未生效，重装时勾选 `Add python.exe to PATH` 并重启。
- **提示「连接失败：HTTP 404」**：B 站已下线旧的 `roomInitStatic` 接口。
  现版本已改用 `room/v1/Room/get_info`，如果你还看到 404，说明用的不是最新版。
- **提示「弹幕信息查询被 B 站风控拦截（code=-352）」**：B 站对 `getDanmuInfo` 加了 WBI 签名校验。
  程序会自动取 WBI 密钥 + buvid 指纹签名，并刷新后重试一次；仍失败就等一会儿再点「连接」。
- **网页版提示「尚未登录」**：先在弹出的浏览器里登录一次并停留在聊天页，再点保存设置
  （之后会一直记住）。想让它重新自动导入你日常浏览器的登录数据，
  先关掉所有浏览器窗口，再删掉 `data/browser_profile` 目录。
- **网页版提示「调试端口没有就绪（超时）」**：Chrome 136+ 只允许在**非默认**数据目录上开调试端口，
  程序已改用专用目录 `data/browser_profile`。若仍超时，请删掉该目录后重试，
  并检查安全软件是否拦截了浏览器的调试端口。
- **API Key 换电脑后失效**：DPAPI 与 Windows 当前用户绑定，换用户/电脑需重新填写。
- **便携版选装 Pillow 后报 `cannot import name '_imaging' from 'PIL'`**：说明装进去的是
  `cp314-t`（自由线程版）轮子。本版已改用 `sysconfig.get_config_var('Py_GIL_DISABLED')`
  精确判断 ABI，重跑一次「安装 / 修复 Pillow」即可。
- **日语区 Windows 上桌面图标点不开 / 快捷方式根本没生成**：安装目录名或快捷方式名里带了
  Shift-JIS 表示不了的汉字（如「译」「酱」「启」「动」），`WScript.Shell` 会静默失败。
  请重新运行安装器把安装目录恢复到 `<install.bat 所在目录>\萌AIちゃん`，或用 `-Dest` 指定 ASCII 路径，并让快捷方式指向 `launch.bat`。
