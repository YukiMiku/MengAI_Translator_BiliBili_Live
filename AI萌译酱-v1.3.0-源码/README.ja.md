# 萌AIちゃん v1.3.0（ポータブル版）

[中文](README.md) | [日本語](README.ja.md)

> 本ソフトの日本語名は **萌AIちゃん（AI萌译酱）** —— インターフェース言語を切り替えると、**ウィンドウタイトル・コンソールタイトル・OBS ドックページのタイトルも一緒に切り替わります**。
>
> バージョン番号の唯一の情報源は `version.py` です。ディレクトリ名・アーカイブ名・ウィンドウタイトル・セルフチェックの出力もこれに合わせます。

v0.5 をベースに改良：**ブラウザでページを操作する方式をやめ、デスクトップウィンドウ（Python tkinter）に変更**し、Web 版の無料翻訳、ローカル用語集ファイルのオープン／インポート、複数の用語集とプリセットの関連付けを追加しました。あわせて**接続後のリアルタイムコメントだけを取得**するようにし、起動時に過去のコメントは表示しません。

## B 站ログイン（ユーザー名の伏せ字を解決）

### 現象

未ログインの場合、B 站はコメント送信者のユーザー名を **`頭文字***`** として返し、**uid を 0** にすることがあります：

```
21:57:06  雪***          ← 実際は 雪初音天下第一可爱
膨らんだら針付きのあの魚？フグじゃない？
```

これは本プログラムの不具合ではありません（プログラム側に伏せ字にする処理は一切なく、文字列は B 站がそのまま配信しています）。
原因は B 站が 2023 年 7 月から導入したリスク管理の方針で、**未ログインの接続は匿名クライアントと判定され、伏せ字にされる**ためです。
[LAPLACE Chat](https://laplace.live/login-sync) の説明にも「哔哩哔哩側の制限により、**伏せ字でない**コメント情報を得るために、お客様のパスポート（cookie）情報を取得**せざるを得ない**」とあります。

### 解決方法：SESSDATA をファイルに書く（ブラウザでのログインは不要）

プログラムは `data/bilibili_cookie.txt` からログイン情報を読み込みます。**ブラウザは起動せず、自動ログインも行いません。**
**しかも必要なのは SESSDATA の 1 つだけ**です：

1. 「接続」ページ → 「**cookie ファイルを開く**」をクリック（メモ帳が開きます。ファイル内に詳しい手順を書いてあります）
2. ブラウザで `https://www.bilibili.com` を開き（ログイン済みであることを確認）→ `F12` を押す
   → **Application / アプリケーション** → **Cookies** → `https://www.bilibili.com`
3. **SESSDATA** を探し、Value をダブルクリックで全選択してコピーし、ファイルの**一番下に新しい行**として次のように書きます：
   ```
   SESSDATA=コピーした値
   ```
4. プログラムに戻って「**読み込んで確認**」をクリック → 成功すると `✅ ログイン済み：<ユーザー名>（uid=xxx）` と表示されます
5. もう一度「接続」をクリック —— 以後のコメントには**完全なユーザー名**と**実際の UID** が付きます

**なぜ SESSDATA だけでよいのか？**（業界標準ライブラリの [blivedm](https://github.com/xfgryujk/blivedm) も同じ方式です）

| 項目 | 必要か | 理由 |
| --- | --- | --- |
| `SESSDATA` | ✅ 必須 | 唯一のセッション資格情報で、blivedm もこれしか見ません |
| `bili_jct` | ❌ 不要 | これは**書き込み操作**用の改ざん防止トークンです。本プログラムはコメントを読むだけです |
| `DedeUserID` | ❌ 不要 | uid はプログラムが `nav` 接口を呼んで自動取得します（`data.mid`） |
| `buvid3` | ❌ 不要 | SPI 接口経由で自動取得済みです |

対応フォーマット（いずれか）：

| フォーマット | 例 |
| --- | --- |
| **SESSDATA だけ書く**（推奨） | `SESSDATA=xxx` |
| SESSDATA の値そのものを貼る | `SESSDATA=` がなくても可 |
| cookie の行全体 | `SESSDATA=xxx; bili_jct=yyy; DedeUserID=123` |
| Cookie-Editor の JSON / Netscape cookies.txt | そのまま丸ごと貼り付け |

### 伏せ字の自動検出

プログラムは伏せ字になった件数をリアルタイムで数え、発生すると上部にバナーを表示します：

```
⚠ 12 件のコメントでユーザー名が伏せ字になっています（「頭文字***」・uid=0）。   [ログインへ]
```

「ログインへ」を押すと「接続」ページへ移動し、cookie ファイルが開きます。

### セキュリティ上の注意（必ずお読みください）

`data/bilibili_cookie.txt` は**あなたの B 站ログイン資格情報そのもの**です。入手されれば、あなたのアカウントとして操作できてしまいます。
LAPLACE もこのリスクについて専用の節を設け、**サブアカウントの使用**を勧めています。

- このファイルを誰にも送らないでください。クラウドストレージにも置かないでください
- コメント取得用のログインには**サブアカウントだけを使う**ことをお勧めします
- この機能を使わないときは「ログイン情報を消去」でファイルをテンプレートに戻せます

### 「ブラウザの cookie データベースから直接読む」について

Chrome / Edge の `Cookies` データベースを直接復号しようと考える方もいますが、**現代のブラウザではこの方法は通用しません**。実測した結論：

| 確認項目 | 結果 |
| --- | --- |
| Edge の bilibili cookie の暗号化形式 | **すべて `v20`（App-Bound Encryption）** |
| DPAPI + AES-GCM で復号できるか | **できない**。`v20` の鍵はブラウザ自身に結び付いており、他プログラムでは開けません |
| Chrome の Cookies データベース | Chrome が排他ロックしているため、共有モードでも読めません（Chrome を終了させる必要があります） |
| Firefox | 平文で保存されるため本来は可能ですが、本機には未インストール |

これはまさに Chrome 127 以降の設計目的 —— 他プログラムによる cookie の窃取を防ぐことです。
そこで本プログラムは「**あなたが一度だけ手動でファイルに書き出す**」方式を採用しました。OS の安全機構を迂回せず、設定も一度だけで済みます。

## コメント欄の背景画像：拡大率 / 位置 / 不透明度

### トリミングなし —— **100% は元画像のそのままのピクセルサイズ**

画像を読み込むとき、コメント欄のサイズに引き伸ばしたり切り取ったりは**しません**：

| 状況 | 動作 |
| --- | --- |
| 画像がコメント欄より**大きい** | 「全体がちょうど収まる」よう自動で等比縮小（例：1600×1000 → 42%）。**ひと目で画像全体が見えます** |
| 画像がコメント欄より**小さい** | **元のサイズ（100%）**のまま中央に表示し、周囲にパネルの地色が出ます |

コメント欄からはみ出した部分はキャンバスが自然に切り取ります（これはキャンバスの挙動で、こちらが「画像を切って」いるわけではありません）。位置スライダーを使えば、キャンバス外の部分を中に移動できます。
ログには元画像のサイズと実際に使った割合が書かれます。例：`元画像 1600x1000、全体が見えるよう 42% に縮小（トリミングなし）`。

### 4 つのコントロール：スライダー + **数値の直接入力**

| コントロール | 範囲 | 説明 |
| --- | --- | --- |
| **背景画像の拡大率** | 10% 〜 400% | **100% = 元画像 1:1** |
| **背景画像の不透明度** | 0% 〜 100% | パネルの地色と混合。0% = 画像が完全に見えない |
| **背景画像の水平位置** | -100% 〜 100% | 0% = 中央。±100% = キャンバス幅の半分だけ移動 |
| **背景画像の垂直位置** | -100% 〜 100% | 0% = 中央。±100% = キャンバス高さの半分だけ移動 |

各コントロールは「**スライダー + 数値ボックス**」です：

- スライダーをドラッグするか、**数値ボックスに直接数字を入力**（Enter / フォーカス移動で確定。`37%` のような書き方も可）
- 範囲外の値は端に丸められます（`9999` と入力 → 400）。不正な入力はそのまま維持されます
- スライダーは**クリックでジャンプ**、ドラッグ、**ホイールで微調整**（±1）に対応
- ボタンは他に 2 つ：「**コメント欄に合わせる**」（画像全体がちょうど収まるよう縮小）、「**初期値に戻す**」（4 項目をまとめてリセット）
- ドラッグ／入力時は**デバウンスして再描画**（約 150ms）。指を離すと `data/config.json` に自動保存されます

### スライダーの配色はテーマに追従（自前描画）

以前使っていた `ttk.Scale` は溝とつまみがシステムテーマで決まるため、ブラック／ブルーなどの暗いプリセットでは**ほとんど見えません**でした。
現在のスライダーは**完全に自前描画**です：溝は入力欄の地色 + 枠線、選択済み部分とつまみはそのテーマの**アクセント色**を使い、4 つの配色すべてではっきり見えます（実測でアクセント色と溝の地色の明度差は 97 〜 152）。

### 透過 PNG の扱い

透過チャンネル付きの PNG（RGBA）を読み込むと、**透明部分はコメント欄の地色が出て、黒背景にはなりません**。

> 黒背景の原因は 2 つの落とし穴です：Tk の `PhotoImage` は PPM に書き出すとき RGB しか持たず、透明ピクセルの RGB は `(0,0,0)` になります。
> Pillow の `convert('RGB')` も同様に `(0,0,0,0)` を `(0,0,0)` にしてしまいます。
> 本プログラムでは**先に透明部分をパネルの地色へ合成**し（Pillow は `Image.alpha_composite`、
> Tk 経路は `image copy` の alpha 合成）、そのうえで拡大縮小と不透明度の混合を行います ——
> 見た目は「完全な透明」と同じで、輪郭に黒い縁も出ません。

> **実装メモ（Tk にはネイティブの透明度がありません）**：不透明度は画像を PPM に書き出し、`bytes.translate` でチャンネルごとのルックアップテーブル混合を行い、
> 結果を `PhotoImage` に戻しています。全体が C レベルのスライス演算なので、760×420 の 1 枚でも数ミリ秒です。
> 拡大縮小は「Tk の整数倍率で目標以上を保証 + 正確なトリミング」の組み合わせで、**どの割合でも正確なピクセルサイズになります**。
>
> Pillow が使える場合（推奨）は LANCZOS の滑らかな拡大縮小 + `Image.blend` を使い、JPG/WEBP にも有効です。

### プリセットは外観も一緒に記憶します

「プリセット保存」は翻訳サービス / システムプロンプト / 同時翻訳数 / 用語集に加えて、次の項目も記憶します：

- **配色**（ホワイト / ブラック / ブルー / ピンク）
- **背景画像のパス**
- **背景画像の拡大率**
- **背景画像の不透明度**
- **背景画像の水平 / 垂直位置**

「プリセット読込」ではこれらも一緒に復元されます（読み込みログに何を復元したかが書かれます）。

## バージョン番号のルール

3 段式の `X.Y.Z` で、完全なルールは `version.py` の先頭に書いてあります（バージョン番号の唯一の情報源）：

| 桁 | 意味 | 更新条件 | 例 |
| --- | --- | --- | --- |
| `X` | メジャー | 機能追加で 2 桁目が 11 になったら繰り上がり | `v1.10.0` → `v2.0.0` |
| `Y` | 機能追加 | 機能を 1 つ追加するごとに +1。範囲は 0 〜 10 | `v1.0.0` → `v1.1.0` |
| `Z` | バグ修正のみ | バグ修正のみのときに +1。**上限なく累積できる** | `v1.0.0` → `v1.0.1` |

- 1 桁目が変わったら、2 桁目と 3 桁目は**すべて 0 に戻ります**。
- **機能追加のときは 3 桁目を 0 に戻します**：`v1.3.7` →（機能追加）→ `v1.4.0`。
- 3 桁目は**2 桁目に繰り上がりません**：バグ修正は常に 3 桁目だけを動かします。

```
v1.0.0 → v1.0.1（バグ修正）→ v1.0.2（バグ修正）→ v1.1.0（機能追加、3 桁目を 0 に）
       → v1.2.0 → v1.2.1（バグ修正）→ v1.3.0（機能追加、3 桁目を再び 0 に）
       → … → v1.10.0（2 桁目の最後の値）→ v2.0.0（繰り上がり、2・3 桁目を 0 に）
```

リリース時は `version.py` の `APP_VERSION` を変更し、ディレクトリ名と zip を同じ名前にしてから `selfcheck.py` を実行し、「内外のバージョン番号が一致している」ことを確認します。

## 外観（「外観」タブ）

### 4 種類の配色、クリックで即切り替え

| ホワイト | ブラック（既定） | ブルー | ピンク |
| --- | --- | --- | --- |
| 明るい地に濃い文字。日中の使用に | 暗い地に明るい文字。長時間でも目が疲れにくい | 濃紺の地でテック感 | 淡いピンクの地でやわらかい印象 |

切り替えは即時反映され `data/config.json` に保存、次回起動時も自動で引き継がれます。

### コメント欄の背景画像

- 「画像を選択」→ 背景画像が**コメント欄全体を覆います**（比率を保ち中央でトリミング、黒い縁なし）。文字は画像の上に表示されます。
- 背景画像は**表示領域に固定**され、コメントをスクロールしても動きません。
- 「画像を消去」でいつでも解除できます。
- 対応フォーマット：
  - **PNG / GIF**：Tk が標準対応。Python が入っていれば使えます。
  - **JPG / WEBP + 滑らかな拡大縮小**：Pillow が必要です。Pillow の欠落や破損を検出すると、
    「外観」ページに具体的な原因が表示され、「**Pillow を導入 / 修復（JPG 対応）**」ボタンでワンクリック修復できます：
    - ソース版（pip あり）：`python -m pip install --force-reinstall pillow` を実行（約 3MB、進行状況はログ欄に表示）；
    - ポータブル版（内蔵ランタイム、**pip なし**）：PyPI からその ABI に合う wheel を直接ダウンロードし、`site-packages` に展開します。
- 目安：明るい画像には「ホワイト / ピンク」、暗い画像には「ブラック / ブルー」が読みやすくなります。

> 実装メモ：コメント欄は `tk.Text` から `tk.Canvas` 描画に変更しました —— Tk のテキストウィジェットは背景画像に対応していないためです。

## 今回のバージョンの変更点

### 追加した機能
1. **ポータブル版：Python 3.14.7 ランタイムを同梱**：アーカイブに実行環境を同梱しました（手作業で追加した `tkinter` を含む）。
   **Python を自分でインストールする必要はありません**。展開すればすぐに使えます。
2. **極小のインストーラー**：`install.bat`（純 ASCII、2.3 KB）+ `install.ps1`（日本語インターフェース、UTF-8 BOM）。
   GitHub Releases からポータブル版をダウンロードし、**`install.bat` と同じフォルダの下の `萌AIちゃん`** に展開してインストール、
   **デスクトップにショートカットを自動作成**し、さらに Pillow を追加インストールするか尋ねます。
3. **インストーラーとプログラムのインターフェースは既定で日本語**：インストールして開くと日本語インターフェースで、
   起動後にいつでも中国語へ切り替えられます。
4. **アップグレード時に `data/` を自動保持**：再インストール / 上書きアップグレードの際、`data/` ディレクトリ全体
   （設定、用語集、ログイン資格情報）が保持されます。
5. **内蔵ランタイムでの Pillow 追加インストール**：ポータブル版のランタイムには**pip がありません**。
   そのため PyPI から適合する wheel を直接ダウンロードし、`site-packages` に展開する方式にしました。

### 修正
- **Pillow wheel の ABI 判定**：以前は `cp314` だけで判定していたため、**`cp314-t`（フリースレッド版）**の wheel を
  誤って選んでしまい、展開後の `import PIL` が `cannot import name '_imaging' from 'PIL'` で失敗しました。
  現在は `sysconfig.get_config_var('Py_GIL_DISABLED')` で ABI を正確に判定するため、もう間違って導入されることはありません。

### 重要：パスとショートカット名に、現在のシステムコードページで表現できない文字を使わない

ここは必ず注意してください —— **日本語版 Windows（ANSI コードページ 932 / Shift-JIS）** では、
「译」「酱」「启」「动」といった文字が **Shift-JIS の文字集合に含まれていません**。これらがパスやショートカット名に入ると問題が起きます：

| 場所 | 結果 |
| --- | --- |
| インストール先ディレクトリ名に上記の漢字を含む | `WScript.Shell` が `TargetPath` を設定できず、**`.lnk` を保存することすらできません**（しかも**成功したふりをします**。エラーは出ません） |
| ショートカットのファイル名に上記の漢字を含む | 同上 |

そのため本バージョンでは次のように固定しました：

- **インストール先は `install.bat` を置いたフォルダの下の `萌AIちゃん`**（バージョン番号を含めないので、ショートカットが長期的に有効です）
- **ショートカットは ASCII の `launch.bat` を指します**
- インストール先の `萌AIちゃん` は**日本語版 Windows の Shift-JIS で表現できる**ため、このままで問題ありません
- 実行するファイル名（`launch.bat` / `check.bat` / `debug.bat`）は**すべて ASCII** です
- **日本語以外の言語版 Windows** では表現できない文字があるため、その場合は `-Dest "D:\MengAI"` のように ASCII のパスを指定してください

### 維持している内容
- 簡素な OBS / 直播姬（ライブ配信ツール）用ドックウィンドウ：`http://127.0.0.1:17890/dock`（表示のみ、操作なし）。
- 中国語 / 日本語 のインターフェース切り替え。
- API キーは Windows DPAPI で暗号化保存（`data/config.json` に平文では保存しません）。
- 日本語のコメントは AI を呼びません。日本語以外は日本語にだけ翻訳します。

> **おすすめの使い方（場面ごとに訳し分ける）**
> 1. 用語集ページで「用語集を新規作成」→ `ゲームA.txt` のようなファイルを作り、その場面専用の訳し方を追加します；
> 2. 「プリセット」ページで名前を入れて「プリセット保存」—— このプリセットが `ゲームA.txt` を記憶します；
> 3. 場面を変えるときは、また用語集を作って別のプリセットを保存します；
> 4. 以後は「プリセット読込」だけで、翻訳サービス・プロンプト・同時翻訳数・そして**対応する用語集**が一緒に切り替わります。
>    2 つの場面が同じ用語集を共有して、同じ語を同じ訳し方に縛られる問題は起きません。

## 起動

### ポータブル版

1. `install.bat` をダブルクリック：GitHub Releases からポータブル版をダウンロードして展開・インストールし、
   **デスクトップにショートカットを自動作成**、さらに Pillow を追加インストールするか尋ねます。
   インストール先は、`install.bat` を置いたフォルダの下の `萌AIちゃん` になります。
2. デスクトップのショートカット（`launch.bat` を指します）をダブルクリックして起動します。
3. インストーラーとプログラムのインターフェースは**既定で日本語**です。起動後にインターフェースから中国語へ切り替えられます。
4. アップグレードはインストーラーをもう一度実行するだけ（上書きインストール）で、`data/` は自動的に保持されます。

### ソース版

1. **python.org の公式版** Python 3.9 以上をインストールします。
   インストール時に次の 2 項目を必ずチェックしてください：
   - `Add python.exe to PATH`
   - `tcl/tk and IDLE`（デスクトップウィンドウに必要。**Microsoft Store 版 Python にはこれがなく、動かせません**）
2. `start.bat` をダブルクリックします。
   - メインプログラムは**Python 標準ライブラリだけを使い、ネット経由で pip インストールするものはありません**。
   - ウィンドウは開いたままになり実行ログを表示します。問題が起きたときはエラー内容がここに直接表示されます。
3. 開いたデスクトップウィンドウで B 站のルームIDを入力 → 「接続」をクリック。
   - **未配信でも接続できます**。状態は「接続済み（現在は未配信）」と表示されます。
   - 翻訳結果を確認したいときは「テストコメント」を押すと、中/英/韓のサンプルコメントが翻訳フロー全体を通ります。

> コマンドラインから手動で実行することもできます：`python app.py`（エラー内容が見えます）

## 起動できないときは

順番に試してください：

1. **`check.bat` をダブルクリック**。
   Python のバージョン、tkinter、プロジェクトファイル、ポート、ディレクトリの権限を 1 項目ずつ確認し、結果を出力します。
   その結果をスクリーンショットで送っていただければ原因を特定できます。
2. コマンドラインで `python app.py --selftest` を実行します。起動できるかだけを確認し、ウィンドウは開きません。
   成功すると `SELFTEST OK` と表示されます。
3. プログラムのディレクトリに `启动错误.txt` が生成されていないか確認します。完全なスタックトレースが入っています。
4. よくある原因：
   - **何も起きない / ウィンドウが一瞬で消える**：以前は `pythonw` でサイレント起動していましたが、
     現在の `start.bat` はコマンドラインで実行する方式に変更したので、エラーは必ず表示されます。
   - **tkinter が見つからないと表示される**：Microsoft Store 版 Python を入れている場合です。アンインストールし、
     <https://www.python.org/downloads/windows/> から公式インストーラーをダウンロードして入れ直し、`tcl/tk and IDLE` をチェックしてください。
   - **Python not found と表示される**：PATH が反映されていません。再インストール時に `Add python.exe to PATH` をチェックするか、
     PC を再起動してから試してください。
   - **ウイルス対策ソフトに遮断される**：フォルダ全体を除外リストに入れてください。
4. 展開が**完全**であることを確認してください（圧縮ファイルの中から直接ダブルクリックして実行していないか）。
   すべての `.py` ファイルが `start.bat` と同じディレクトリにある必要があります。

### Web版（DeepSeek / ChatGPT）の使い方 —— 追加コンポーネントのインストールは不要

Web 版は**本プログラム専用のブラウザウィンドウ**を使います（お使いの Chrome / Edge を再利用し、カーネルのダウンロードも playwright の導入も行いません）。

#### なぜ普段使っているあのウィンドウを使わないのか？

**Chrome 136** 以降、Google はセキュリティ上の理由から**「既定のデータディレクトリ」でリモートデバッグを有効にすることを禁止**しました
（[公式アナウンス](https://developer.chrome.com/blog/remote-debugging-port?hl=ja)）。
つまり、プログラムが普段お使いの Chrome にアタッチする**方法はありません** —— これは Chrome の制限であり、本プログラムの制限ではありません。
Google が示す代替案が「カスタムのデータディレクトリを使う」ことで、本プログラムもこの方式を採用しています。

#### 使い方

1. 「翻訳サービス」で「DeepSeek Web版」または「ChatGPT Web版」を選びます。
2. 「Web版を開いてログイン」をクリックします。
   - 初回は**普段のブラウザのログインデータを本プログラム専用ディレクトリへインポート**しようとします。
   - **DeepSeek**：ログイン状態は `localStorage`（暗号化なし）にあるため引き継げ、開いた時点でログイン済みです。
   - **ChatGPT**：ログイン状態は暗号化された Cookie です。Chrome 127 以降は「アプリ結合暗号化」が有効なため、
     Cookie を**別のディレクトリへ移行できません**（これは Cookie のコピーによる窃取を防ぐ Google の設計です）。
     そのため ChatGPT は**この専用ウィンドウで一度ログイン**してください。以後は記憶されます。
3. 以後の翻訳はすべてこの専用ウィンドウで行われ、プログラムがその中で**タブを新規作成 / 再利用**します。

> 専用ディレクトリへのインポートは 1 回だけで、以後の起動で既にログイン済みのセッションを**上書きしません**。
> 完全にやり直したい場合は `data/browser_profile` ディレクトリを削除してください（削除すると再ログインが必要です）。

#### その他の説明

- **先に Web 側で「深い思考」と「ウェブ検索」をオフにすることをお勧めします**：この 2 つのスイッチはコメント 1 件ごとの応答を大幅に遅くし、
  さらに「深い思考」は思考過程を先に出力します。プログラムは**思考ブロックを自動で読み飛ばし、最終的な訳文だけを取得**しますが、
  オフにすると数倍速くなります。
- 専用ディレクトリは `data/browser_profile` です。完全にやり直したい（ログインデータを再インポートしたい）場合はこのディレクトリを削除してください。
- 2 つの Web 版は**同じブラウザインスタンスを共有**します（それぞれ 1 タブを使用）。
- プログラムは**自分が起動した**ブラウザインスタンスだけを再利用し、他プログラムが使用中のデバッグポートに誤って接続しません。
  展開先ディレクトリを変えて記録が失われても、デバッグ用ブラウザが開いていればそのまま再利用し、**2 つ目のブラウザを開くことはありません**。
- 入力 / 送信には**ブラウザネイティブの入力イベント + 実際の Enter** を使うため、コメント 1 件ごとに独立した新しい質問になります。
  「前の質問を上書きする」ことはありません。ログには実際の送信方法が出力されます（`送信方法：入力=native，送信=ENTER`）。
- プログラムは**自動化のマーカーを注入しません**。そのため「Chrome は自動テストソフトウェアによって制御されています」や
  「サポートされていないコマンドラインフラグ」といった黄色いバーの警告は出ません。
- Web 版は逐次翻訳です（同時翻訳数は 1 に固定）。速度は API より遅くなります。
- Web 版はサイトのページ構造に依存します。DeepSeek / ChatGPT の改版で入力欄が見つからなくなった場合は、
  ログを送っていただければ `browser.py` の JS スニペットを調整します。

## ローカル用語集ファイル

- 既定の用語集ファイル：`data/glossary.txt`。1 行に 1 項目：
  ```
  元の語 => 日本語訳 # 備考
  ```
  例：
  ```
  草 => w # 笑いを表す
  可爱 => かわいい
  草 => くさ（笑）      ← 訳文内の括弧はそのまま残ります
  ```
- **備考として認識するのは `#` だけ**です：`元の語 => 訳 # 備考`。
  訳文の末尾の「（…）」は訳文そのものとして扱われます（旧版では誤って備考としていましたが修正済み）。
- 「用語集ファイルを開く」はメモ帳で編集。「用語集をインポート」はさらに CSV（列：source,target,note,enabled）と
  JSON（配列 `[{"source","target","note","enabled"}]`）に対応します。
- 用語集は用語ルールとして翻訳モデルに渡され、指定した訳し方が優先されます。
- 行末に `[禁用]` と書くとその項目を無効にできます。例：`元の語 => 訳 [禁用]`。

### 複数の用語集（場面ごとに訳し分ける）

- 「**用語集を新規作成**」ボタン：名前を入力すると `data/` の下に新しい用語集ファイルを作成します（例：`ゲームA.txt`、`日常.txt`）。
- 「**現在の用語集**」ドロップダウン：いつでも既存の用語集を切り替えられます。
- プリセットと組み合わせて使うのがおすすめです：
  1. 用語集を作る → 語を追加 → 「プリセット」ページで「プリセット保存」；
  2. そのプリセットがこの用語集を記憶し、プリセットのドロップダウンに `用語集:ゲームA.txt` と表示されます；
  3. 以後は「プリセット読込」で、翻訳サービス / プロンプト / 同時翻訳数 / **用語集** が一緒に切り替わります。
- こうすれば同じ語（例：「草」）でもプリセットごとに全く違う日本語訳にでき、互いに干渉しません。

## よくある質問

- **start.bat をダブルクリックしても反応しない**：まず `check.bat` をダブルクリックして結果を確認してください。または `python app.py` を直接実行してエラーを見てください。
- **tkinter が見つからないと表示される**：Microsoft Store 版 Python です。python.org の公式版に入れ替え、`tcl/tk and IDLE` をチェックしてください。
- **Python not found と表示される**：PATH が反映されていません。再インストール時に `Add python.exe to PATH` をチェックして再起動してください。
- **「接続失敗：HTTP 404」と表示される**：B 站が旧 `roomInitStatic` 接口を廃止しました。
  現行版は `room/v1/Room/get_info` に変更済みです。まだ 404 が出る場合は最新版ではありません。
- **「コメント情報の取得が B 站のリスク管理に遮断されました（code=-352）」と表示される**：B 站が `getDanmuInfo` に WBI 署名検証を追加しました。
  プログラムは WBI キー + buvid フィンガープリント署名を自動取得し、更新して 1 回リトライします。それでも失敗する場合は少し待ってから「接続」を押してください。
- **Web 版で「まだログインしていません」と表示される**：先に開いたブラウザで一度ログインし、チャットページを開いたままにしてから設定を保存してください
  （以後は記憶されます）。普段のブラウザのログインデータをもう一度自動インポートさせたい場合は、
  すべてのブラウザウィンドウを閉じてから `data/browser_profile` ディレクトリを削除してください。
- **Web 版で「デバッグポートが準備できません（タイムアウト）」と表示される**：Chrome 136+ は**既定以外**のデータディレクトリでしかデバッグポートを開けません。
  プログラムは専用ディレクトリ `data/browser_profile` を使うように変更済みです。それでもタイムアウトする場合は、このディレクトリを削除して再試行し、
  セキュリティソフトがブラウザのデバッグポートを遮断していないか確認してください。
- **API キーが PC を変えると無効になる**：DPAPI は Windows の現在のユーザーに紐づくため、ユーザー / PC を変えた場合は再入力が必要です。
- **ポータブル版で Pillow を追加インストールした後に `cannot import name '_imaging' from 'PIL'` が出る**：入ったのは
  `cp314-t`（フリースレッド版）の wheel です。本バージョンは `sysconfig.get_config_var('Py_GIL_DISABLED')` で
  ABI を正確に判定するよう変更しました。「Pillow を導入 / 修復（JPG 対応）」をもう一度実行してください。
- **日本語版 Windows でデスクトップのアイコンが開けない / ショートカットが作られない**：インストール先ディレクトリ名かショートカット名に、
  Shift-JIS で表現できない漢字（「译」「酱」「启」「动」など）が含まれています。`WScript.Shell` は静かに失敗します。
  インストーラーをもう一度実行してインストール先を `<install.bat のフォルダ>\萌AIちゃん` に戻すか、`-Dest` で ASCII のパスを指定し、ショートカットは `launch.bat` を指すようにしてください。
